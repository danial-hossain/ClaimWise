# ClaimWise Database Schema & Architecture

## Overview
ClaimWise uses Supabase PostgreSQL with the `pgvector` extension for storing structured policy/claim data alongside dense vector embeddings generated by BGE-M3 (1024 dimensions). All tables containing user data are protected by PostgreSQL **Row Level Security (RLS)** with explicit, non-permissive ownership policies.

---

## Tables & Entity Relationship

### 1. `profiles`
Maps directly 1:1 with `auth.users(id)` from Supabase Auth.
- `id`: `UUID` (Primary Key, references `auth.users(id) ON DELETE CASCADE`)
- `email`: `TEXT`
- `full_name`: `TEXT`
- `avatar_url`: `TEXT`
- `created_at`: `TIMESTAMPTZ`
- `updated_at`: `TIMESTAMPTZ`

### 2. `policies`
Represents an insurance policy document uploaded and parsed.
- `id`: `UUID` (Primary Key, default `gen_random_uuid()`)
- `user_id`: `UUID` (Foreign Key -> `profiles.id`)
- `title`: `TEXT` (e.g. "Comprehensive Health Advantage 2026")
- `insurer_name`: `TEXT` (e.g. "BlueCross", "Geico", "Allianz")
- `policy_number`: `TEXT`
- `policy_type`: `TEXT` (Enum: `health`, `auto`, `home`, `life`, `travel`, `disability`, `other`)
- `coverage_start_date`: `DATE`
- `coverage_end_date`: `DATE`
- `deductible_amount_cents`: `BIGINT` (Deterministic rules engine uses cents to avoid float errors)
- `out_of_pocket_max_cents`: `BIGINT`
- `annual_limit_cents`: `BIGINT`
- `status`: `TEXT` (`active`, `expired`, `cancelled`, `draft`)
- `raw_document_url`: `TEXT`
- `document_sha256`: `TEXT`
- `created_at`, `updated_at`: `TIMESTAMPTZ`

### 3. `policy_chunks`
Text sections and clauses extracted from policy PDFs for hybrid search (BM25 + pgvector).
- `id`: `UUID` (Primary Key)
- `policy_id`: `UUID` (Foreign Key -> `policies.id ON DELETE CASCADE`)
- `chunk_index`: `INTEGER`
- `page_number`: `INTEGER`
- `section_heading`: `TEXT`
- `clause_identifier`: `TEXT` (e.g. "Section 4.2(b) Pre-existing conditions")
- `content`: `TEXT` (Raw verbatim text chunk)
- `token_count`: `INTEGER`
- `embedding`: `vector(1024)` (pgvector representation for BGE-M3 model)
- `metadata`: `JSONB` (Page coordinates, bounding boxes for PDF highlight citations)
- `created_at`: `TIMESTAMPTZ`

### 4. `claims`
Insurance claims managed, investigated, or prepared for submission.
- `id`: `UUID` (Primary Key)
- `user_id`: `UUID` (Foreign Key -> `profiles.id`)
- `policy_id`: `UUID` (Foreign Key -> `policies.id ON DELETE SET NULL`)
- `claim_reference`: `TEXT` (External claim identifier or internal tracking code)
- `incident_date`: `DATE`
- `claimed_amount_cents`: `BIGINT`
- `approved_amount_cents`: `BIGINT`
- `status`: `TEXT` (`draft`, `evidence_gathering`, `analyzed`, `sandbox_submitted`, `insurer_rejected`, `in_dispute`, `approved`, `closed`)
- `insurer_reason_code`: `TEXT` (e.g. "DENIAL_CODE_104_OUT_OF_NETWORK")
- `insurer_denial_notes`: `TEXT`
- `ai_investigation_summary`: `TEXT`
- `line_items`: `JSONB` (Itemized bill charges, CPT codes, dates)
- `adjudicated_items`: `JSONB` (Itemized evaluations with citations)
- `eob_data`: `JSONB` (Explanation of Benefits breakdown)
- `sandbox_submission`: `JSONB` (Simulated mock payer remittance response)
- `appeal_draft`: `JSONB` (Structured, editable denial appeal draft, citations, checklist)
- `created_at`, `updated_at`: `TIMESTAMPTZ`

### 5. `claim_documents`
Untrusted files uploaded as claim evidence (bills, denial letters, repair bills).
- `id`: `UUID` (Primary Key)
- `claim_id`: `UUID` (Foreign Key -> `claims.id ON DELETE CASCADE`)
- `user_id`: `UUID` (Foreign Key -> `profiles.id`)
- `document_type`: `TEXT` (`medical_bill`, `repair_estimate`, `denial_letter`, `receipt`, `police_report`, `appeal_letter`, `other`)
- `file_name`: `TEXT`
- `file_url`: `TEXT`
- `file_size_bytes`: `BIGINT`
- `mime_type`: `TEXT`
- `ocr_extracted_text`: `TEXT`
- `created_at`: `TIMESTAMPTZ`

### 6. `comparisons`
Multi-policy comparison snapshots and cost simulations (Migration 003).
- `id`: `UUID` (Primary Key)
- `user_id`: `UUID` (Foreign Key -> `profiles.id`)
- `title`: `TEXT`
- `policy_ids`: `JSONB` (Array of policy IDs compared)
- `comparison_data`: `JSONB` (Side-by-side attributes, citations, transparent status)
- `cost_simulation`: `JSONB` (Deterministic rules engine calculations, caveats)
- `status`: `TEXT` (`completed`, `pending`, `failed`)
- `created_at`, `updated_at`: `TIMESTAMPTZ`

### 7. `audit_logs` (Updated in Migration 004: Tamper-Evident SHA-256 Hash Chaining)
Cryptographically chained, immutable audit trail linking sensitive operations.
- `id`: `UUID` (Primary Key, default `gen_random_uuid()`)
- `sequence_number`: `BIGINT` (Monotonically increasing sequence; enforced unique)
- `user_id`: `UUID` (Foreign Key -> `profiles.id ON DELETE SET NULL`)
- `action`: `TEXT` (e.g. `policy.upload`, `claim.adjudicate`, `appeal.export_pdf`, `comparison.create`)
- `resource_type`: `TEXT` (e.g. `policy`, `claim`, `appeal`, `comparison`)
- `resource_id`: `TEXT` (ID of affected resource)
- `outcome`: `TEXT` (`success`, `failed`, `denied`)
- `metadata`: `JSONB` (Canonical, sanitized metadata with automatic credential/PHI redaction)
- `previous_hash`: `TEXT` (SHA-256 hash of immediately preceding audit event; genesis uses 64 zeros)
- `event_hash`: `TEXT` (SHA-256 digest over canonical JSON representation [RFC 8785])
- `schema_version`: `TEXT` (Default '1.0.0')
- `created_at`: `TIMESTAMPTZ` (UTC creation timestamp)
- **RLS Policies**: Strictly append-only. Users may `SELECT` where `auth.uid() = user_id`, `INSERT` with matching identity. `UPDATE` and `DELETE` operations are prohibited.

### 8. `consents`
Explicit records of user consents for AI processing, data parsing, and sandbox submissions.
- `id`: `UUID` (Primary Key)
- `user_id`: `UUID` (Foreign Key -> `profiles.id`)
- `consent_type`: `TEXT` (`data_processing`, `ai_analysis`, `sandbox_claim_submission`, `terms_of_service`)
- `granted`: `BOOLEAN`
- `policy_version`: `TEXT`
- `ip_address`: `INET`
- `granted_at`: `TIMESTAMPTZ`
- `revoked_at`: `TIMESTAMPTZ`

## Row Level Security (RLS) Strategy

All tables enforce PostgreSQL RLS (`ENABLE ROW LEVEL SECURITY`). Every policy checks the caller's verified identity via `auth.uid()`:

1. **Direct Ownership**: Tables like `profiles`, `policies`, `claims`, `comparisons`, and `consents` check `auth.uid() = user_id`.
2. **Indirect Ownership**: Sub-resource tables like `policy_chunks` verify ownership transitively by checking that the parent `policies` row belongs to `auth.uid()`.
3. **Audit Immutability**: `audit_logs` allows users to select only their records; records cannot be updated or deleted by normal users.
4. **Service Role Security**: The backend service role key bypasses RLS strictly when executing system background jobs, but frontend clients only access the database through authenticated user sessions or validated FastAPI endpoints.
